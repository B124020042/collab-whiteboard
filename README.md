# 協作白板 Collaborative Whiteboard

企業資訊通訊期末專案：多人透過網路在同一張畫布上即時畫圖。
只使用 Python 標準函式庫 (`asyncio`、`socket`、`threading`、`tkinter`)，不需安裝任何套件。

## 功能

- **即時同步**：任何人畫的線會立刻出現在同房間所有人的畫面上
- **畫筆工具**：8 色調色盤＋自訂顏色、粗細調整、橡皮擦
- **復原 (Ctrl+Z)**：只會復原「自己」畫的最後一筆，不會動到別人的
- **清除畫布**、**儲存** (PostScript 圖檔或 JSON 筆跡資料)
- **他人游標**：即時顯示其他人的滑鼠位置與暱稱 (每人固定顏色)
- **多房間**：`--room` 指定房間，各房間畫布互相獨立
- **線上名單**、加入 / 離開通知、暱稱重複自動加編號
- **後加入者自動補齊畫面**：伺服器保存筆跡，新連線會收到完整重播
- **斷線自動重連**：網路恢復後自動重新連線並同步到最新畫面
- **Demo 機器人** (`bot.py`)：自動畫玫瑰線 / 螺旋，單人也能展示多人協作

## 執行方式

需要 Python 3.8 以上。tkinter 通常已內建；若出現 `No module named 'tkinter'`：
Ubuntu/Debian 執行 `sudo apt install python3-tk`，macOS (Homebrew) 執行 `brew install python-tk`。

```bash
# 1. 啟動伺服器 (預設 port 9100)
python3 server.py

# 2. 開多個客戶端 (可以在不同電腦，用 --host 指定伺服器 IP)
python3 client.py --name alice
python3 client.py --name bob --host 192.168.1.10
python3 client.py --name carol --room design     # 另一個房間

# 3. (選用) 讓機器人一起畫
python3 bot.py --name robot --count 5

# 4. 自動化測試 (不需要 GUI)
python3 test_server.py
```

跨電腦連線時，伺服器那台的防火牆要開放 TCP 9100。

## 架構

```
┌──────────── client.py ────────────┐            ┌──────── server.py ────────┐
│ 主執行緒 (tkinter)                 │            │ asyncio 事件迴圈 (單執行緒) │
│  滑鼠事件 → 本機先畫 → 累積點座標   │──TCP──────▶│  rooms: {房間: Room}       │
│  每 30ms 批次送出 draw             │  JSON      │   ├ users   線上使用者      │
│  每 15ms 從 queue 取訊息更新畫面 ◀─┐│  lines     │   └ strokes 筆跡 (有序)     │
│ 網路執行緒 (Net)                   ││◀───────────│  轉發給同房間其他人         │
│  連線 / 自動重連 / 讀取 → queue ───┘│            │  新加入者 → 完整重播        │
└────────────────────────────────────┘            └───────────────────────────┘
```

### 通訊協定

TCP 之上自訂應用層協定：每則訊息是一行 UTF-8 JSON，以 `\n` 分隔，解決 TCP 位元組串流沒有訊息邊界 (黏包) 的問題。完整定義見 `protocol.py`。

| 方向 | type | 內容 |
|------|------|------|
| C→S | `hello` | 暱稱、房間 |
| C→S | `draw` | 筆跡 id、顏色、粗細、一批點座標 |
| C→S | `cursor` / `undo` / `clear` | 游標位置 / 復原 / 清除 |
| S→C | `welcome` | 最終暱稱、線上名單、目前所有筆跡 |
| S→C | `draw` / `cursor` | 轉發他人的筆跡、游標 |
| S→C | `remove` / `clear` | 移除某筆 / 清空 |
| S→C | `user_join` / `user_leave` | 使用者進出 |

### 設計重點

1. **比例座標**：座標一律用 0~1 傳送，各客戶端依自己的視窗大小換算，視窗縮放後也會重繪。
2. **批次傳送**：滑鼠移動事件每秒可達上百次。先在本機立即畫出 (零延遲手感)，點座標累積後每 30ms 送一批，封包數大幅下降。每批會多帶前一批的最後一點，讓線段連續。
3. **游標節流**：游標位置最多每 50ms 送一次；它是「最新值才重要」的資料，丟掉舊值不影響結果 (這類資料也適合改用 UDP)。
4. **GUI 執行緒安全**：tkinter 只能在主執行緒操作，所以網路執行緒只把訊息放進 `queue.Queue`，主執行緒用 `root.after()` 定時取出處理。
5. **一致性**：伺服器接收順序就是最終順序；客戶端每次 (重新) 連線都以伺服器的 `welcome` 完整狀態為準。
6. **權限與防呆**：只能接續 / 復原自己的筆跡；伺服器檢查顏色格式、粗細範圍、座標範圍，壞掉的 JSON 直接忽略，不會讓伺服器崩潰。每房間最多保存 5000 筆。

## 測試

`test_server.py` 會啟動伺服器，用多個原始 socket 客戶端驗證：
筆跡同步、不回送給自己、後加入者重播、復原只影響自己、房間隔離、游標座標限制、清除畫布、暱稱重複處理、離線通知、惡意或錯誤輸入、機器人壓力測試。

| `protocol.py` | 共用協定與編解碼 |
| `bot.py` | 自動畫圖的 demo 機器人 |
| `test_server.py` | 自動化測試 |

## 可延伸方向

- TLS 加密 (`ssl` 模組包裝 socket)
- 形狀工具 (矩形、圓形、文字)、側邊聊天室
- 筆跡存入 SQLite，伺服器重啟後畫布仍在
- 用 WebSocket 做網頁版客戶端
